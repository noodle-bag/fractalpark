## 1. Что вы можете делать сегодня

FractalPark сейчас предоставляет 677 записей Standard: 513 опубликованных Definition
и 164 удерживаемых Record.

Для опубликованного Record вы можете:

- проверить его идентичность, происхождение, решение по правам, редакцию исходного кода и Profile;
- просмотреть или скачать закреплённый исходный код Definition `.frm`;
- открыть закреплённые Definition и Profile в Explore; и
- начать анонимный Remix, не меняя исходный код Standard.

Удерживаемый Record объясняет, почему он недоступен. Для него нет действия source, run, edit или
Remix. Присутствие в каталоге не означает доступности во время выполнения.

Отдельный FRM Editor остаётся поверхностью разработки с совместимостью Classic.
Активация канонического FRM-like v1 writer и import по-прежнему закрыта шлюзом. Примеры в этом
руководстве — исполняемые v1 Definition, проверенные промышленным v1 parser, созданием артефактов
CPU/GLSL и двумя конечными шагами CPU, но текущий отдельный Editor не является местом для вставки
канонического v1. Используйте Formula Records для изучения активного исходного кода Standard; для
рабочего процесса Classic-compatible Editor используйте существующее FRM Guide.

## 2. Чтение опубликованного Definition

Опубликованный Definition начинается с трёх семантических директив:

```text
; @language: frm-like/1
; @stdlib: 1
; @numeric-profile: standard32
```

Они закрепляют язык, словарь функций и численное поведение. Они выглядят как
комментарии, поэтому читатели Classic могут их допустить, но FractalPark рассматривает их как
семантический ввод. Удаление, дублирование, размещение после заголовка формулы или
изменение любой из них делает Definition недействительным. Перестановка трёх директив во
вступлении допустима; канонический вывод восстанавливает показанный выше порядок.

Перенесённый исходный код также может содержать одну необязательную директиву
`; @classic-guards: zero-division, floored-log, hyperbolic-clamp`.
Канонический вывод размещает её сразу после `@numeric-profile`. Она фиксирует
проверенные доказательства совместимости, поэтому авторы НЕ ДОЛЖНЫ добавлять, удалять или изменять её
вручную; см. [нормативный §5](../specs/frm-like-language-v1.md#5-standard-library-v1).

Тело содержит одно имя формулы и три обязательных исполняемых раздела:

```frm
; @language: frm-like/1
; @stdlib: 1
; @numeric-profile: standard32
FirstOrbit {
  init:
    z = 0
  loop:
    z = z ^ 2 + c
  bailout:
    |z| <= 4
}
```

Здесь `|z| <= 4` означает радиус 4. Порог квадрата модуля Classic, равный `4`,
соответствует `|z| <= 2`, поэтому при переносе нужно передавать смысл, а не
копировать число.

Унарный минус также отличается от распространённого и Classic прочтения, где `^` имеет приоритет:
v1 читает `-z ^ 2` как `(-z) ^ 2`. При переносе добавляйте скобки, выражающие
задуманный знак, вместо копирования неоднозначной записи.

Читайте его в порядке итерации:

1. `init` задаёт состояние орбиты один раз для каждого пикселя.
2. Перед каждым `loop` FractalPark сохраняет снимок `z` как `zPrev`.
3. `loop` обновляет орбиту в порядке исходного кода.
4. `bailout` отвечает на вопрос «следует ли продолжать итерацию?» Ложный результат останавливает её.

`|z|` — истинный комплексный модуль, а не квадрат модуля. Поэтому пример
продолжается, пока радиус орбиты не превышает 4.

Formula Record закрепляет точный исходный код через `sourceRevision` и отдельно закрепляет
Profile. Profile владеет камерой, числом итераций, режимом, константой Julia, палитрой
и раскраской. Эти параметры представления не относятся к Definition.

## 3. Написание Definition

Начните с минимальной структуры выше. Имена формул и переменные используют буквы ASCII,
цифры и подчёркивания; первый символ не может быть цифрой. Оставляйте
по одному оператору в каждой физической строке.

Полезные системные значения и значения host:

- `pixel`: текущая координата плоскости;
- `c`: константа формулы, выбранная во время выполнения;
- `z`: доступное для записи состояние орбиты;
- `zPrev`: поддерживаемое средой выполнения значение орбиты предыдущей итерации;
- `LastSqr`: поддерживаемый средой выполнения квадрат модуля `z` в конце
  последнего завершённого `loop`. Для конечного `z`, квадрат модуля которого превышает
  binary32, этот канал принятия решения насыщается положительной бесконечностью, не завершая
  шаг; чтение этого значения в исходном коде всё равно даёт `nonFinite`;
- `ismand`: режим плоскости параметров (`true`) или Julia (`false`);
- `pi`, `e` и `maxit`;
- входы совместимости Classic `p1`-`p5`, которые можно читать напрямую. Несвязанная
  ячейка — комплексный ноль на CPU и ДОЛЖНА оставаться комплексным нулём в
  соответствующем GLSL host. Связь `classic pN` заставляет неименованную ячейку и именованный
  параметр разрешаться в одно значение; и
- ячейки функций Classic `fn1`-`fn4`, которым перед вызовом нужны соответствующие именованные
  параметры функций со связями `classic fnN`.

`zPrev` и `LastSqr` не являются внешними входами host и НЕ ДОЛЖНЫ переопределяться.
Доступные для выражений состояния функции см. в [кратком справочнике стандартной библиотеки](#standard-library-quick-reference).

Этот Definition работает и в режиме плоскости параметров, и в режиме Julia:

```frm
; @language: frm-like/1
; @stdlib: 1
; @numeric-profile: standard32
ModeAwarePower {
  parameters:
    power: real = 2 domain [1, 16]
  init:
    if ismand
      z = 0
    else
      z = pixel
    endif
  loop:
    z = z ^ power + c
  bailout:
    |z| <= 64
}
```

Не присваивайте значения системному значению или ячейке Classic из §3, параметру,
константе или имени stdlib. `z` — единственное доступное для записи системное значение. Новое допустимое
имя присваивания создаёт локальную переменную, но дальнейшие присваивания должны сохранять тот же тип.

Выражения поддерживают арифметические, сравнительные и логические операторы, унарные минус и
not, вызовы функций, скобки, комплексные литералы и полосы модуля. `^`
правоассоциативен. FractalPark вычисляет в порядке исходного кода и слева направо, а не
безмолвно переставляет операции с плавающей точкой. Каноническая форма formatter v1
НЕ ДОЛЖНА содержать вложенные полосы модуля; для внутреннего модуля используйте `cabs(...)`. Унарный минус связывается
сильнее возведения в степень, поэтому `-z ^ 2` означает `(-z) ^ 2`.

## 4. Добавление параметров

Поместите необязательный раздел `parameters` перед `init`. Параметр имеет один из трёх
типов:

- `real`: конечный скаляр, при желании с включающим `domain [min, max]`;
- `complex`: литеральное значение по умолчанию `(real, imaginary)`; или
- `function`: имя унарной функции stdlib.

Именованный параметр может фиксировать уникальную связь Classic. Связывайте параметры `real` или `complex`
только с `p1`-`p5`, а параметры функций — только с `fn1`-`fn4`.
Связи поддерживают перенос и взаимодействие; в исходном коде следует использовать именованный
параметр.

```frm
; @language: frm-like/1
; @stdlib: 1
; @numeric-profile: standard32
FunctionGarden {
  parameters:
    scale: real = 0.5 domain [0, 2] classic p1
    offset: complex = (-0.2, 0.1) classic p2
    transform: function = sin classic fn1
  init:
    z = pixel
  loop:
    z = transform(z) * scale + offset + c / maxit
  bailout:
    LastSqr < 576
}
```

Жёсткие домены — проверяемые семантические пределы. Если значения вне рекомендованного диапазона
остаются допустимыми, вместо этого поместите мягкий диапазон в Profile или Record.

Параметры функций принимают имена унарных stdlib, такие как `sqr`, `sin`, `log` или
`identity`. У `atan2` два аргумента, и её нельзя выбрать параметром функции. Если выбраны
`real`, `imag` или `cabs`, их скалярный результат преобразуется в комплексное значение
с нулевой мнимой частью. В примере также используется поддерживаемый средой квадрат модуля
`LastSqr` как порог продолжения и потолок итераций host `maxit`, чтобы масштабировать вклад `c`.
Полный выбираемый набор см. в [кратком справочнике стандартной библиотеки](#standard-library-quick-reference).

## 5. Использование состояния и управляющего потока

`if`, `elseif`, `else` и `endif` работают с булевыми условиями. Локальную переменную можно
читать после ветвления, только если её инициализировал каждый путь. Это отклоняет формулы,
которые зависели бы от устаревших или специфичных для backend значений.

Присваивание компонента обновляет одну часть уже инициализированного комплексного значения:

```frm
; @language: frm-like/1
; @stdlib: 1
; @numeric-profile: standard32
OrbitMemory {
  parameters:
    feedback: complex = (0.3, -0.12)
    bias: real = 0.05 domain [-1, 1]
  init:
    z = pixel
  loop:
    z = z + zPrev * feedback
    previous = z
    if real(z) >= 0
      z = sqr(z) + c
      real(z) = real(z) + bias
    else
      z = cos(z) + c
      imag(z) = imag(z) - bias
    endif
    z = z + bias * previous
  bailout:
    |z| < 48
}
```

Здесь `previous` захватывается после начального обновления обратной связи и до
ветвления, тогда как `zPrev` — снимок среды выполнения, сделанный непосредственно перед `loop`.
Они не взаимозаменяемы: `zPrev` — входящее значение орбиты, а
`previous` — промежуточное значение, используемое после ветвления.

<a id="standard-library-quick-reference"></a>
### Краткий справочник стандартной библиотеки

stdlib включает:

- арифметику и проекции: `abs`, `sqr`, `sqrt`, `exp`, `log`, `recip`,
  `conj`, `flip`, `real`, `imag`, `cabs`, `round`, `atan2`, `identity`;
- круговые функции: `sin`, `cos`, `tan`, `asin`, `acos`, `atan`; и
- гиперболические функции: `sinh`, `cosh`, `tanh`, `asinh`, `acosh`, `atanh`,
  `cotanh`, а также функцию совместимости `cosxx`.

Помните, что `abs(z)` применяется покомпонентно, тогда как `cabs(z)` и `|z|` возвращают
комплексный модуль. Деление на ноль, `log(0)` и другие обязательные неконечные значения
завершают работу событием `nonFinite`, если перенесённый Definition не содержит
конкретную защиту Classic, подтверждённую доказательствами.

## 6. Диагностика отклонённого Definition

Начинайте с первой стабильной причины. Последующие ошибки часто являются следствиями
того же пропущенного раздела, некорректного токена или необъявленного значения.

Практический порядок проверки:

1. **Преамбула:** все три обязательные директивы присутствуют по одному разу и до
   заголовка; любую проверенную необязательную директиву `@classic-guards` сохраняйте без изменений.
2. **Форма:** одна формула; упорядоченные `parameters`, `init`, `loop`, `bailout`;
   ровно одно выражение bailout; нет завершающего исполняемого текста.
3. **Имена:** идентификаторы ASCII, нет конфликта с зарезервированными именами и дубликатов
   параметров или связей Classic.
4. **Типы:** булевы условия ветвления/bailout, вызываемые функции, согласованный
   тип локальной переменной, инициализированная цель компонента.
5. **Определённое присваивание:** каждая читаемая локальная переменная инициализирована на каждом пути.
6. **Безопасность:** исходный код, параметры, локальные переменные, AST, глубина выражений, операторы,
   управляющий поток и сгенерированный шейдер остаются внутри оболочки v1.
7. **Время выполнения после принятия:** синтаксически допустимая формула всё ещё может
   завершиться с `nonFinite`; это свидетельство времени выполнения, а не разрешение заменить
   формулу.

Распространённые исправления:

| Отклонение | Правильный ответ |
|---|---|
| `invalid-semantic-directives` | Восстановите точные значения языка, stdlib и NumericProfile |
| `invalid-section-order` | Переместите `parameters` перед `init`, затем `loop`, затем `bailout` |
| `undeclared-read` | Сначала присвойте локальную переменную или объявите параметр; не угадывайте значение хоста |
| `possibly-uninitialized-read` | Инициализируйте локальную переменную в каждой ветви до её чтения |
| `unmapped-function-slot` | Объявите параметр функции с соответствующей связью `classic fnN` |
| `bailout-not-boolean` | Используйте явное сравнение, например `|z| < 4` |
| `source-too-large` | Уменьшите исходный ввод и вывод formatter до не более чем 65 536 байтов UTF-8 |
| `generated-shader-too-large` | Упростите Definition; не запрашивайте более высокий публичный предел |

Известное отклонение v0.4.19: вложенный модуль в скобках сейчас может разбираться parser, но
не является каноническим, не проходит обратное преобразование formatter и ДОЛЖЕН удерживаться проверкой публикации.
Оно отслеживается в [нормативной ссылке §8](../specs/frm-like-language-v1.md#8-canonicalization-revisions-and-conformance),
а активация writer заблокирована, пока frontend не начнёт его отклонять.

Соответствующий инструмент отклоняет неподдерживаемую пунктуацию, макросы, определяемые пользователем
функции, несколько формул, произвольные директивы и завершающий исполняемый
контент. Неподдерживаемые конструкции отклоняются, а не выполняются с изменённым значением.

## 7. Редакции, Remix и переносимость

Два хеша отвечают на разные вопросы:

- `sourceRevision` определяет точные байты UTF-8 закреплённого исходного ресурса
  Definition.
- `semanticHash` определяет каноническое типизированное значение. Комментарии, несущественное
  форматирование и имя формулы не меняют его; исполняемые правки меняют.

Опубликованный reader хеширует байты исходного кода точно в предоставленном виде. Нормализация
CRLF/CR-to-LF применяется только при разборе и никогда к `sourceRevision`; окончания строк,
комментарии, форматирование или завершающий LF поэтому могут изменить `sourceRevision`,
не меняя `semanticHash`. Writer, проходящий шлюз, строже:
он должен выдавать детерминированную форму formatter и проходить Safety Envelope
до сохранения или публикации.

У Profile есть собственная редакция. Изменение камеры или палитры не переписывает
смысл формулы. Аналогично, сборка backend имеет собственную редакцию и не может стать
вторым источником истины.

Standard Definition неизменяем при закреплённой редакции. **Open** запускает этот
Definition и Profile. **Remix** создаёт редактируемый анонимный контекст с
замороженной родословной; он не изменяет и не выдаёт себя за Standard Record. Параметры передачи
расходуются один раз и удаляются из URL. Сохранение и восстановление из облака остаются отдельными
операциями идентификации и авторизации.

Переносимая работа следует контракту ресурсов reader-first. Самодостаточная работа
закрепляет или встраивает Definition, вычисленные значения параметров, Profile, язык,
stdlib и NumericProfile, необходимые для воспроизведения. Контракт требует, чтобы неподдерживаемые
будущие Profile открывались только для чтения, а не незаметно понижались. v1 сейчас
предоставляет только `standard32`, а регрессионный шлюз C10 всё ещё ожидается, поэтому это
поведение для будущих Profile не заявляется как проверенное поведение продукта сегодня.
Активация writer и миграция Production — отдельные шлюзы релиза; это руководство их не подразумевает.

## 8. Classic `.frm` и отдельный Editor

Classic `.frm` — диалект import с другой грамматикой исходного кода и
отдельной осью совместимости `frmSemanticsVersion`. Он может содержать несколько
записей, классические заголовки, блоки, разделённые двоеточиями, неявные ячейки и историческую
семантику, которую канонический v1 намеренно не копирует как синтаксис разработки.

Отдельный FRM Editor сейчас сканирует и компилирует эту поверхность, совместимую с Classic.
Его общие примеры не содержат трёх канонических директив v1 или раздела v1 `parameters`.
Не считайте успешную компиляцию Classic Editor доказательством, что исходный код имеет форму
канонического formatter v1.

И наоборот, не вставляйте каноническую форму formatter v1 в текущий
отдельный Editor и не делайте вывод, что язык не поддерживается, когда устаревшая поверхность
разработки её отклоняет. Используйте действие Source Formula Record, чтобы изучить
или скачать опубликованный исходный код v1, и его действия Open/Remix, чтобы запустить закреплённую
опубликованную среду выполнения. Поддержка канонического v1 writer/import должна пройти собственный шлюз активации,
прежде чем изменятся правила доступности в этом разделе или нормативной ссылке §9.

Для выбора Classic, замороженной визуальной совместимости, диагностики strict-v2 и поведения
