# FractalPark v0.4.15 Regression Matrix

- Status: Active
- Date: 2026-08-01
- Target release: FractalPark v0.4.15

## Purpose

v0.4.15 delivers the web creation loop in three large pull requests that all
merge to `main` while the cloud feature switch stays off for users. Every
commit must remain a stable handoff point, every pull request has an
explicit exit gate, and production enablement is a separate manual gate
after the final merge.

A commit is complete only when its affected contract is implemented and
fully tested. Tests are part of the feature commit and are not deferred to
a final test-only cleanup commit. Each commit carries its affected tests,
en/zh messages, error states, and compatibility handling, and passes its own
commit gate without relying on a later commit to fix a red intermediate
state.

## Governing Contracts

This matrix verifies the release-specific implementation of:

- [Web Creation Loop v1](../specs/web-creation-loop-v1.md);
- [ADR 0005: Same-Origin Cloud Session](../adr/0005-same-origin-cloud-session.md);
- [Fractal Content and Creation Model](../specs/fractal-content-and-creation-model.md);
- [Fractal Document v2 and Envelope v1](../specs/fractal-document-v2.md);
- [Artwork and Location Route Contract](../specs/artwork-and-location-routes.md);
- [Analytics Event Schema v1](../specs/analytics-events-v1.md); and
- [ADR 0004: Remix Source Metadata](../adr/0004-remix-source-metadata.md).

The v0.4.13 regression matrix remains the compatibility baseline: v0.4.15
must not regress any v0.4.13 area while the cloud switch is off.

## Gate Levels

### Commit gate

Every code commit must:

- be independently buildable and revertible;
- include tests for new or changed behavior;
- keep existing routes and UI usable with the cloud switch off;
- include all affected English and Chinese messages and error states;
- pass `npm run lint`, `npm run test:run`, and `npm run build`;
- pass the relevant focused Playwright specs for changed user flows;
- for schema changes, pass the database test suite against a local Supabase
  stack.

Documentation-only commits require internal link and contract review but do
not need browser execution when no executable behavior changes.

### Pull request gates

Each PR is one slice-level gate. The next PR does not begin with known
blocking failures from the previous one.

**PR 1 (foundation and security)** exits when:

- contract documents pass repository review with no either/or placeholders
  in API route, error, cache, CSRF, envelope, or SQL contracts;
- the project builds and runs with every Supabase/SMTP variable absent;
- with the switch off, Gallery, Explore, local save, import/export, and the
  official Collection behave unchanged;
- ordinary previews hold no staging credentials and stay off; only the
  designated integration preview can write staging; an old preview fails
  closed on an incompatible schema;
- migrations replay from an empty database and cover forward upgrade,
  constraints, indexes, unique keys, and serial execution;
- database tests cover owner A, owner B, anonymous, public reads, withdrawn
  attribution, user-scoped RPC, service-role rejection of ordinary owner
  RPCs, and server-only boundaries;
- the integration preview verifies same-origin OTP login, logout, refresh,
  expiry, cookie rotation, CSRF/Origin, no-store on auth/private responses,
  provider-native rate limits, FractalPark email/IP rate limits, direct
  endpoint bypass protection, and the disable path;
- `CloudArtworkEnvelopeV1` budget fixtures and the controlled public
  thumbnail render path pass, including the placeholder fallback that never
  publishes client images;
- a small staging recovery check proves auth identity UUIDs survive or are
  auditably remapped, and owner/RLS relations hold after re-login;
- OTP delivery is verified from mainland-China network conditions to at
  least Feishu, QQ, 163, and one international mailbox;
- the integration preview sends a real 1 MiB attachment over SMTP port 465,
  exercises failed/unknown classification, stale-pending convergence, and
  the independent email disable switch;
- secrets exist only in hosting-platform configuration, never in the
  repository or logs;
- lint, unit, build, affected Playwright, database tests, and
  `git diff --check` all pass.

**PR 2 (complete creation loop)** exits when the integration preview runs
the full anonymous → local save → OTP → cloud draft → re-edit → publish →
Community → remix loop, and the ownership, immutability, provenance,
local–cloud binding, Community routing, thumbnail, email-preference, and
failure-preservation tests listed in the PR contract all pass. Production
remains off.

**PR 3 (hardening and release readiness)** exits when withdrawal,
hide/restore, account deletion, cleanup convergence, cache revocation,
policy pages, the full permission matrix, cross-device acceptance, and the
new-project recovery drill all pass. Merging PR 3 still does not enable
production.

### Production enablement gate

After PR 3 merges, production enablement is a separate manual sequence:
create production resources with explicit maintainer approval; generate and
verify the pre-migration backup; run production migrations and check
environment isolation; complete manual acceptance of login, save, publish,
open, remix, withdraw, and email with maintainer test accounts; then set
`FRACTALPARK_CREATION_CLOUD_ENABLED=true` and redeploy from the same
accepted commit.

## Representative Environments

- Local development with the local Supabase stack: schema, RLS, RPC, and
  migration tests.
- The designated integration preview against staging: the only environment
  with cloud enabled; synthetic data and maintainer test mailboxes only.
- Production: cloud switch off throughout the rollout; smoke-checked after
  every merge to prove existing behavior is unchanged.

Representative viewports and WebGL evidence rules follow the v0.4.13 matrix:
390 × 844, 768 × 1024, 1440 × 900, 1920 × 1200, and 2560 × 1440 where
layout is affected. Real desktop and mobile devices are required for the
PR 3 acceptance pass.

## Compatibility Fixtures

v0.4.15 retains every v0.4.13 fixture and adds:

- legacy `myfrac-saved-fractals` records and Envelope-backed local artwork;
- `StoredArtworkRecordV2` reads of v1/legacy records without background
  rewrites;
- Document v1/v2 and future read-only documents against cloud write
  rejection;
- envelopes with portable formula assets: allowed for drafts and export,
  rejected for publish;
- malformed, over-budget, and non-canonical envelopes;
- withdrawn/hidden publications and their tombstone projections;
- storage-unavailable, quota-exceeded, and invalid local data states.

## Incremental Development Rules

- Land contract documents before schema, and schema before any product UI.
- Migrations are incremental, serial, and owned by one designated executor
  per PR; cross-PR forward-compatibility windows are declared in advance.
- Do not expose navigation, UI entry points, or API routes to incomplete
  cloud flows; the switch keeps them invisible and uncalled.
- Do not leave the frontend dependent on a follow-up commit to compile or
  run.
- One representative validation batch first, then the remaining homogeneous
  scope in bulk.
- Update this matrix whenever an accepted requirement changes the affected
  surfaces, data contracts, or fallback behavior.

## Test Evidence

Each PR handoff records:

- commit SHAs and migration versions applied;
- commands run and results, including database tests;
- integration-preview verification evidence;
- OTP delivery and SMTP attachment evidence;
- known non-blocking issues;
- compatibility fixtures exercised;
- manual checks required before the next gate.
