# v0.4.19 Slice 0 Baseline and Formula Route Probe

- Baseline release: `v0.4.18@1f9d4f76e20816d6eb7337973e65b98d231fd902`
- Measured: 2026-08-15
- Node: `v22.23.1`
- npm: `10.9.8`
- Next.js: `16.1.6` with webpack
- Build heap ceiling: `NODE_OPTIONS=--max-old-space-size=3072`

This document records a released-code baseline and a route strategy decision. It
is not a claim about v0.4.19 browser, GPU, or real-device performance.

## Build baseline

Both builds completed with exit status 0 from a clean detached release checkout.
The second sample reused the build cache so cold and warm behavior remain
separate.

| sample | compile | static generation | pages | wall | max RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| initial | 38.8 s | 39.0 s | 594 | 137.9 s tool duration | not captured |
| warm repeat | 14.6 s | 34.0 s | 594 | 95.28 s | 874,096 KiB / 853.6 MiB |

The warm repeat recorded zero swaps and exit status 0. These values are only
comparable when the candidate SHA, Node/npm/Next versions, heap ceiling, cache
state, worker count, and host are recorded together.

The final pre-commit Slice 0 candidate tree also built successfully on the same
host with the same heap ceiling: compile 16.0 s, static generation 31.8 s for 594
pages, wall 89.92 s, max RSS 951,988 KiB / 929.7 MiB, zero swaps, exit status 0.
Compared with the warm released repeat, max RSS was 76.1 MiB / 8.9% higher; two
samples are not enough to call that a regression, so later candidate comparisons
must retain cache state and repeat count.

Reproduction command:

```bash
NODE_OPTIONS=--max-old-space-size=3072 /usr/bin/time -v npm run build
```

## Released directory and route shape

- Formula catalog: 94 entries.
- Formula Atlas projection: 94 entries across seven families.
- Serialized `buildFormulaAtlas('en')` result: 230,638 UTF-8 bytes. This is a
  pure-function serialization baseline, not a measured network transfer.
- Family counts: classic 27, burning-ship 11, newton 14, magnet 2, phoenix 2,
  transcendental 21, exotic 17.
- Prerender manifest: 580 route entries after the 594-page build.
- Formula-related prerendered routes: 168.
- Explore prerendered routes: seven, one per supported locale.
- Existing Formula Record pages: 21 slugs × seven locales = 147 pages.

A Node-only resolver microbenchmark over 1,000,000 calls returned 0.383 and
0.539 microseconds per call in two sequential rounds. This only demonstrates
that current in-memory selection lookup is not the dominant cost. It is not a
cold/hot interaction measurement and cannot substitute for browser marks.

## Route strategy decision

Do **not** pre-generate all 677 Formula IDs across all seven locales.

- 677 × 7 would add 4,739 ID pages.
- Replacing the current 147 Guide pages with those pages would raise the rough
  static total from 594 to 5,186, about 8.73× the current page count.
- The approved content contract also rejects indexing locale fallback or thin
  Formula Records merely to fill a matrix.

Use one canonical dynamic Formula ID route with selective pre-generation:

1. Keep `dynamicParams` enabled for the long tail.
2. Pre-generate only reviewed, indexable Formula ID + locale pairs, initially
   the 30–50 priority teaching set rather than 677 × 7.
3. Cache route-local Record data by `FormulaID + recordRevision + locale`.
4. Keep canonical source, runtime payload, profiles, and other locales out of
   the route's initial directory payload; load a selected asset by ID/revision.
5. Put only reviewed/indexable locale pairs in sitemap and alternates.
6. Invalidate a single Record cache entry when its Record revision changes;
   do not rebuild unrelated IDs.

This matches Next.js `generateStaticParams` semantics while avoiding a build
fan-out that the product does not need:
<https://nextjs.org/docs/app/api-reference/functions/generate-static-params>.

## Candidate comparison contract

Every later comparison must record:

- candidate Commit SHA;
- cold or warm cache state;
- browser and version;
- device/CPU/GPU and renderer;
- network profile;
- dataset/formula count and selected asset revision;
- sample count and percentile, not a single best run.

## Still unmeasured

The following remain pending and must not be inferred from build or Node data:

- Atlas route network payload and first useful paint;
- facet commit → filtered-list paint;
- Library DOM and heap bounds at 677 entries;
- Formula select → loading state → first correct canvas frame;
- separate cold asset/runtime load and hot cached load;
- preview decode timing;
- runtime memory and GPU recovery;
- 320/390 px interaction behavior;
- real-device WebGL correctness.

Required harness: Playwright/browser `performance.mark` instrumentation plus
real-device runs. Use 50 selection samples, 30 hot samples, and 20 cold samples,
reported separately with the comparison contract above.
