### 4.5 Review state/provenance and indexability

```ts
type ReviewStage = 'not-started' | 'source-drafted' | 'technical-reviewed' |
  'locale-reviewed' | 'maintainer-approved' | 'superseded' | 'blocked';
type ActorKind = 'human-maintainer'|'model-reviewer'|'automated-contract';
interface EvidenceRef { kind: 'content-hash'|'diff-ref'|'source-id'|'anchor-export'|'review-artifact'|'test-run'; value: string; }
interface ReviewEvent { stage: ReviewStage; at: string; actorId: string; actorKind: ActorKind; actorRole: 'author'|'technical-reviewer'|'locale-reviewer'|'maintainer'; evidenceRefs: EvidenceRef[]; note?: string; }
interface ReviewState { current: ReviewStage; events: ReviewEvent[]; approvedContentHash?: string; }
type Delivery = 'not-delivered' | 'fallback-browse-only' | 'delivered';
```

Transitions are monotonic except `superseded`/`blocked`: `not-started → source-drafted → technical-reviewed → locale-reviewed → maintainer-approved`. `blocked` requires an already-started unit and may resume only through an exact-hash-evidenced `source-drafted` event; `superseded` is terminal. The review ledger is the only source of truth; units contain no authorable review stage, and any mirrored/derived stage mismatch fails the build and policy closed. Every event requires a documented actor role plus nonempty actor/evidence identity. In this single-maintainer project, the same maintainer may close technical and approval roles, but `maintainer-approved` requires actual bound technical/locale review evidence; model and automated actors can never emit the maintainer stage. A new English hash, revision/hash mismatch, or material factual change returns affected locales to `source-drafted`; a language-only correction after technical review returns that locale to `locale-reviewed`. Only a maintainer event may create `maintainer-approved` or delivery eligibility. AI-generated material, if used internally, is only `source-drafted`; public copy must not self-promote AI.

`contentHash` is always recomputed from canonical JSON. English units are hashed as the complete canonical English fact unit. Locale units exclude only their own `contentHash` field from the hash payload; `englishContentHash` remains inside that payload and must equal the recomputed English hash. Ledger hashes must equal these recomputed values, while every `not-started` unit must have null ledger hashes and no content entity. Any invalidation/regression event must cite the exact recomputed ledger-bound content hash; a merely well-formed but unrelated SHA-256 is not evidence.

Approved English-canonical content served under `/en/` is `delivery=delivered`, `contentLocale='en'`, and becomes content-eligible for later Commit 21 SEO decisions. The same English content served under any non-English path is controlled fallback: `delivery=fallback-browse-only`, `contentLocale='en'`, `robots='noindex,follow'`. It is never localized delivery and never SEO-set or `x-default` evidence. The calculation fails closed: missing unit, non-approved ledger state, stale binding, ledger/unit hash divergence, or absent required sections results in fallback/noindex.

## 7. Risks and decisions

- **Current legacy identity mismatch:** `src/content/formula-manifest.ts` contains historical Guide identifiers while the new catalog uses UUIDs. Recommendation: add an explicit legacy-to-UUID editorial mapping in 20a; do not mutate old prose IDs incidentally.
- **Duplicate-looking display names:** runtime rows can share display names (notably `mandelbrot`). Recommendation: all joins and file names use UUID, never display name; tests must catch name-only selection.
- **Stable semantic node IDs:** the runtime index exposes `semanticHash`, not the annotation inventory needed by teaching prose. Resolution: 20a delivers a generated public-safe semantic anchor export keyed by source revision and tests byte-identical regeneration; 20c remains blocked unless all 50 rows resolve.
- **Historical claims:** existing Guide text has references, but new teaching prose must not infer authorship/history from name similarity or source code. Recommendation: make `sourceIds` mandatory for every factual/provenance assertion and allow only neutral explanatory prose otherwise.
- **Review capacity:** 350 content units (50 English fact units plus 300 localized editorial units) plus seven manuals are substantial. Recommendation: the five 10-formula batches and locale-independent fallback make the work auditable without falsely reporting completion.
- **Indexing pressure:** fallback is useful for browsing but makes thin localized pages risky. Recommendation: implement only noindex fallback in 20d and defer selective SEO expansion to its separately authorized later work.
