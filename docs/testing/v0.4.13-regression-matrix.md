# FractalPark v0.4.13 Regression Matrix

- Status: Active
- Date: 2026-07-26
- Target release: FractalPark v0.4.13

## Purpose

v0.4.13 changes shared state consumers and several public surfaces over a
multi-week development period. Every implementation commit must remain a
stable handoff point, while slice and release gates provide progressively
broader regression coverage.

A commit is complete only when its affected contract is implemented and fully
tested. Tests are part of the feature commit and are not deferred to a final
test-only cleanup commit.

## Governing Contracts

This matrix verifies the release-specific implementation of:

- [Fractal Content and Creation Model](../specs/fractal-content-and-creation-model.md);
- [Formula Content Manifest and FRM Surface Contract](../specs/formula-content-manifest.md);
- [Artwork and Location Route Contract](../specs/artwork-and-location-routes.md);
- [Analytics Event Schema v1](../specs/analytics-events-v1.md); and

## Gate Levels

### Commit gate

Every code commit must:

- be independently buildable and revertible;
- include tests for new or changed behavior;
- keep existing routes and UI usable;
- include all affected English and Chinese messages;
- pass `npm run lint`, `npm run test:run`, and `npm run build`;
- pass the relevant focused Playwright specs for changed user flows.

Documentation-only commits require internal link and contract review but do
not need browser execution when no executable behavior changes.

Generated-asset commits must include dimension, manifest-reference, and source
state validation plus the tests for every surface that consumes the assets.

### Slice gate

At the end of each implementation slice:

- run the full Playwright suite;
- run both locales for affected public routes;
- check mobile, standard desktop, and wide desktop layouts;
- exercise no-JavaScript SSR behavior where applicable;
- rerun legacy URL, saved-artwork, custom-formula, and project import fixtures;
- record the gate result in the pull request or development log.

The next slice does not begin with known blocking failures from the previous
slice.

### Release-candidate gate

The release candidate must pass:

```bash
npm run lint
npm run test:run
npm run build
npx playwright test
```

It also requires production-mode smoke testing, sitemap and metadata
inspection, representative visual review, accessibility keyboard checks, and
WebGL resource/performance observation.

## Representative Viewports

- Mobile: 390 × 844
- Tablet: 768 × 1024
- Standard desktop: 1440 × 900
- Wide desktop: 1920 × 1200
- Ultra-wide Gallery check: 2560 × 1440

Exact pixel snapshots are not required for animated WebGL frames because GPU
output may vary. Tests should assert stable state and controls; representative
static posters and generated assets receive deterministic dimension and visual
review.

## Compatibility Fixtures

The release must retain coverage for:

- legacy saved artwork under `myfrac-saved-fractals`;
- current Envelope-backed local artwork;
- Document v1 and v2;
- valid future read-only Documents;
- malformed project files;
- legacy preset and Explore query URLs;
- custom formula records created before the standalone Editor;
- missing, invalid, and conflicting imported formula assets;
- storage unavailable, quota exceeded, and invalid local data.

Compatibility readers may outlive the UI that created older records. Their
removal requires a separate accepted migration decision.

## Incremental Development Rules

- Add a shared model or adapter before migrating its consumers.
- Migrate one coherent consumer or vertical flow per commit.
- Do not expose navigation to an incomplete route.
- Do not leave the frontend dependent on a follow-up commit to compile or run.
- Keep compatibility adapters until all consumers and rollback checks pass.
- Perform one representative validation batch, then execute the remaining
  homogeneous content or asset scope in bulk.
- Update this matrix whenever an accepted requirement changes the affected
  surfaces, data contracts, or fallback behavior.

## Test Evidence

Each slice handoff records:

- commit SHA;
- commands run and results;
- focused browser specs and viewports;
- known non-blocking issues;
- compatibility fixtures exercised;
- screenshots or manual checks required before the next bulk step.
