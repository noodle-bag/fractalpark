# v0.4.19 Standard Library performance gate

This gate is fail-closed. It separates deterministic CI checks from reference-browser and real-device evidence so a software renderer cannot be reported as a real GPU result.

## Frozen contract

The source of truth is `resources/formula-library/v1/performance-gates.v1.json`.

The gate binds the complete 677-row decision ledger to the exact 513-row published runtime and preview sets. It also caps the public index, manifest, definition, and preview payloads. The initial Library page is fixed at 48 rows so catalog growth cannot silently turn into an unbounded DOM.

Every browser result uses the measurement tuple:

1. **source bindings** — SHA-256 for the decision ledger, runtime index/manifest, preview manifest, Library client/selection code, canvas renderer hook, and gate config;
2. **environment** — browser/version, OS, viewport, CPU, WebGL vendor/renderer, network/cache mode, and whether the GPU is real or emulated;
3. **samples** — raw values, not only summaries: 20 Library opens, 20 heap deltas, 20 preview decodes, 20 cold selections, 30 hot selections, and 50 facet commits. Every value must be finite and non-negative; the gate computes p95 itself.

A selection starts immediately before the directory row is activated and ends only after the matching `data-rendered-formula-id` is present and `gl.finish()` has completed. A facet sample ends after the pressed state and two animation frames, so it includes filtered-list paint. Preview timing uses `HTMLImageElement.decode()`.

## Commands

```bash
npm run formula:performance:verify
npm run formula:performance:measure -- \
  --base-url=http://127.0.0.1:3000 \
  --physical-device \
  --device-model='MacBook Pro 14-inch (M4 Pro)' \
  --os-version='macOS 15.x' \
  --input-method=mouse-keyboard \
  --output=.artifacts/standard-library-performance.json
npm run formula:performance:release
```

`formula:performance:verify` is the deterministic CI gate. It validates exact decision/runtime/preview sets and static budgets.

`formula:performance:measure` records the raw browser samples and environment tuple. A release-qualifying run requires `WEBGL_debug_renderer_info`, a positively identified hardware vendor/renderer, explicit physical-device metadata, and a non-emulated mouse/keyboard run. Unknown, generic, virtualized, or software renderers fail closed. `--allow-software` is diagnostic-only and produces `releaseQualifying: false` without selection samples.

`formula:performance:release` additionally requires `resources/formula-library/v1/performance-evidence.v1.json`, current source hashes, minimum sample counts, browser/build budgets, accessibility evidence, a rollback drill, and every required real-device row. Missing, stale, emulated, or failing evidence exits non-zero.

## Renderer policy

SwiftShader remains useful for shader conformance and fail-closed browser automation, but it is not a release performance reference. On the current constrained Linux host, the three-basis functional switch test passes while taking minutes; that result must not be relabeled as a real-GPU latency measurement.

Reference browser timing must positively identify a supported hardware renderer; merely avoiding the current software-renderer denylist is insufficient. Device rows must identify the physical model, OS/browser version, viewport, input method, GPU vendor/renderer, physical-versus-emulator state, and a repository-local raw artifact. Each artifact lives under `resources/formula-library/v1/device-evidence/`, is bound by SHA-256, repeats the exact environment tuple, and contains at least three named passing raw samples. The reference Chromium artifact additionally contains every raw performance sample copied into the release evidence; the verifier compares them byte-for-byte at the JSON level.

Required release rows:

- desktop Chromium with a real GPU;
- desktop Firefox with a real GPU;
- iPhone Safari touch flow;
- iPad Safari touch flow;
- Android Chrome touch flow;
- screen-reader and keyboard flow.

## Accessibility and rollback drill

Automated checks cover bounded keyboard-reachable controls, focus trapping/restoration, live loading status, `aria-busy`, and visible selection failures. Manual evidence must still cover screen-reader announcements and touch-device behavior.

The rollback drill blocks release unless all of these preserve the last-known-good formula and canvas:

1. published index unavailable;
2. definition fetch/parse/compile failure;
3. in-flight selection cancellation or supersession;
4. invalid cold/warm Standard URL parameters;
5. Library feature removal or runtime-reader rollback leaves built-in formulas usable.

Evidence is stored as five separately required scenarios rather than one aggregate checkbox. The index-loading component test covers (1); runtime compile/tamper tests plus the HTTP-503 E2E cover (2); coordinator tests cover (3); crafted-URL E2E covers (4); and the reader-first/writer-pinned test covers (5). The HTTP-503 E2E additionally asserts that the dialog remains open, the alert is exposed, the URL is unchanged, and the previous canvas keeps its rendered formula ID.

## Budget changes

Do not widen a budget in the same change that regresses it without separate evidence and review. A legitimate budget revision must include the old raw samples, new raw samples, cause, user impact, and rollback decision. Static asset caps should normally be reduced by architectural work (pagination, sharding, lazy loading), not raised to absorb growth.
