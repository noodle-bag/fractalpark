# v0.4.19 Standard Library performance gate

This gate is fail-closed. It separates deterministic CI checks from reference-browser and real-device evidence so a software renderer cannot be reported as a real GPU result.

## Frozen contract

The source of truth is `resources/formula-library/v1/performance-gates.v1.json`.

The gate binds decision revision 4 to the exact 534-row published runtime and preview sets. It also caps the public index, manifest, definition, and preview payloads. The initial Library page is fixed at 48 rows so catalog growth cannot silently turn into an unbounded DOM.

Every browser result uses the complete measurement tuple:

1. **Git commit and target URL** — the measured code revision and exact Preview/Staging origin; release verification requires the measured commit to be a strict ancestor of the checked-out release SHA, re-reads every bound source from that commit, and rejects the descendant unless every changed path is evidence-only;
2. **source bindings** — SHA-256 for the decision ledger, runtime index/manifest, preview manifest, Library client/selection code, canvas renderer hook, tests, workflows, and gate config;
3. **environment** — browser/version, OS, viewport, CPU, WebGL vendor/renderer, cold/hot cache protocol, and whether the GPU is real or emulated;
4. **samples** — raw values, not only summaries: 20 Library opens, 20 heap deltas, 20 preview decodes, 20 cold selections, 30 hot selections, 50 selected/loading paints, and 50 facet commits. Every value must be finite and non-negative; the gate computes each percentile from the raw arrays.

The approved interaction budgets are enforced without substitution: facet activation to filtered-list next paint is P75 ≤100 ms; every formula activation to selected/loading paint is ≤100 ms; hot cached activation to the first correct canvas frame is P95 ≤300 ms; cold activation is P95 ≤2 s on desktop and ≤3 s on mobile. Selected/loading timing keeps the activation mark, waits until `aria-busy` is observable, and then crosses two `requestAnimationFrame` turns so the endpoint is after presentation rather than merely before a paint callback. Each cold sample uses a fresh isolated browser context so the definition/runtime cache is cleared. Hot samples reuse three preloaded definitions and compiled programs, and both initial and hot `.frm` request counts must be zero. A correct-frame sample ends only after the matching `data-rendered-formula-id` is present and `gl.finish()` has completed. Preview timing uses `HTMLImageElement.decode()`.

## Commands

```bash
npm run formula:performance:verify
npm run build
npm run formula:performance:verify-build
npm run formula:performance:measure -- \
  --base-url=http://127.0.0.1:3000 \
  --physical-device \
  --device-model='MacBook Pro 14-inch (M4 Pro)' \
  --os-version='macOS 15.x' \
  --input-method=mouse-keyboard \
  --output=.artifacts/standard-library-performance.json
FORMULA_PERFORMANCE_CANDIDATE_SHA=<release-checkout-sha> \
FORMULA_PERFORMANCE_TARGET_URL=https://<preview-or-staging-origin> \
  npm run formula:performance:release
```

`formula:performance:verify` is the deterministic pre-build CI gate. It validates exact decision/runtime/preview sets, static budgets, evidence schemas, and source hashes. All 534 definition filenames and `definitionPath` values must match the runtime index, and SHA-256 of every definition body must equal its `sourceRevision`. After `npm run build`, `formula:performance:verify-build` scans `.next/server` and `.next/static`, rejects copied `.frm` files, and rejects any exact or JSON-escaped published-only definition body in the initial build output. The already shipped native overlap is frozen by both count (`89`) and SHA-256 of the sorted definition source-revision filenames; because each filename is itself independently revalidated against the definition body, a same-count substitution fails. It is not misreported as lazy published-library transfer. CI and the release workflow run this audit after the candidate build.

`formula:performance:measure` records the raw browser samples and environment tuple. A release-qualifying run requires `WEBGL_debug_renderer_info`, a positively identified hardware vendor/renderer, explicit physical-device metadata, and a non-emulated mouse/keyboard run. Unknown, generic, virtualized, or software renderers fail closed. `--allow-software` is diagnostic-only and produces `releaseQualifying: false` without selection samples.

`formula:performance:release` includes the build-output audit and additionally requires `resources/formula-library/v1/performance-evidence.v1.json`, current source hashes, exact sample counts, browser/build budgets, a source-bound accessibility receipt, the approved rollback matrix, and every required real-device row. The release workflow injects its immutable `${{ github.sha }}` as `FORMULA_PERFORMANCE_CANDIDATE_SHA` and repository variable `FORMULA_PERFORMANCE_TARGET_URL`; the verifier requires the former to equal checkout `HEAD`, the measured commit to be its strict ancestor with byte-identical bound sources, and every browser/device/rollback artifact to use the latter exact public HTTPS origin. Any descendant change outside `performance-evidence.v1.json`, `device-evidence/`, and `rollback-evidence/` is rejected, so the only permitted difference after measurement is the evidence envelope itself. Localhost, IP literals, credentials, paths, and `.local` origins are rejected. Missing, stale, emulated, or failing evidence exits non-zero.

## Renderer policy

SwiftShader remains useful for shader conformance and fail-closed browser automation, but it is not a release performance reference. On the current constrained Linux host, the three-basis functional switch test passes while taking minutes; that result must not be relabeled as a real-GPU latency measurement.

Reference browser timing must positively identify a supported hardware renderer; merely avoiding the current software-renderer denylist is insufficient. Device rows must identify the measured Git commit and target URL plus the physical model, OS/browser version, viewport, input method, GPU vendor/renderer, and physical-versus-emulator state. Each artifact lives under `resources/formula-library/v1/device-evidence/`, is bound by SHA-256, repeats the exact environment tuple, records the cache protocol, and includes the complete 50/50/20/30 interaction arrays plus zero initial/hot definition requests. Desktop artifacts use the 2 s cold budget and must pass walking-skeleton, 320 px, 390 px, and GPU-recovery tasks; touch artifacts use 3 s and must pass walking-skeleton, touch selection, and GPU-recovery tasks. The reference Chromium artifact additionally contains every raw performance sample copied into the release evidence; the verifier compares them byte-for-byte at the JSON level. The screen-reader artifact uses named task receipts instead of timing arrays and must pass the exact five-task matrix: open/close focus, loading announcement, selection busy state, failure alert with last-known-good preservation, and keyboard pagination/facets.

Required release rows:

- desktop Chromium with a real GPU;
- desktop Firefox with a real GPU;
- iPhone Safari touch flow;
- iPad Safari touch flow;
- Android Chrome touch flow;
- screen-reader and keyboard flow.

## Accessibility and rollback drill

Automated checks cover bounded keyboard-reachable controls, focus trapping/restoration, live loading status, `aria-busy`, and visible selection failures. Manual evidence must still cover screen-reader announcements and touch-device behavior.

The rollback contract deliberately separates resilience cases from release rollback. Existing automated tests still cover index/definition failure, supersession, hostile URLs, and last-known-good canvas behavior, but those checks cannot stand in for the approved rollback matrix. Release requires all of the following:

1. **writer off** — disabling v3 writes leaves the reader floor intact;
2. **feature off** — removing the published runtime leaves built-in formulas usable;
3. **last-known-good runtime** — the pinned manifest/index/definition set still validates and runs;
4. **reader floor** — v1/v2 and legacy readable documents remain readable after writer rollback;
5. **alias resolver** — the frozen exact alias mapping remains deterministic and unknown aliases fail closed;
6. **deployed Preview/Staging rollback** — an actual SHA-bound deployment drill preserves the last-known-good formula/canvas and records its target URL.

The first five scenarios are separate source-bound machine artifacts under `resources/formula-library/v1/rollback-evidence/`. The deployed drill is separately required and may remain `pending` during development, but `formula:performance:release` refuses to pass until its artifact is present, hash-bound, and marked `pass`. That artifact must record all seven passing steps: backup current, disable writer, disable feature, activate the LKG runtime, verify the reader floor, verify the alias resolver, and restore current. Likewise, accessibility remains pending until the screen-reader device artifact is attached; prose alone is not accepted as evidence.

## Budget changes

Do not widen a budget in the same change that regresses it without separate evidence and review. A legitimate budget revision must include the old raw samples, new raw samples, cause, user impact, and rollback decision. Static asset caps should normally be reduced by architectural work (pagination, sharding, lazy loading), not raised to absorb growth.
